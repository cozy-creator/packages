# PAN2 and LTX-2.5 execution qualification

The source tools generate real video through the installed Cozy CLI on a single H200 NVL. This report separates that execution evidence from model publication, package installation, and the ComfyUI comparison. Receipts and playable exports are retained in `/home/fidika/cozy_v2/outputs/video-models-20261115`.

## Source cohort

- Packages: `pan2` and `ltx-2.5`, first-party `generate` tools named `video`, labelled **PAN2** and **LTX-2.5**. Both accept an optional first frame and up to 20 seconds at 24 fps.
- Worker: Cozy/TensorD 0.25.0, Runtime 0.46.0, TensorFS 0.25.1, Python 3.12.3, PyTorch 2.15.0+cu132. H200 NVL, 143771 MiB reported VRAM, driver 595.91.07. The worker is explicitly held on these released versions.
- PAN2: HF `82f54c6cea3e20a9c451b61d7360016e5970503d`, native 1248×704, 50 Euler steps, CFG 2.5, flow shift 9. Preserve the source's mixed BF16/F32 transformer and F32 Wan VAE. Qwen's text encoder and tokenizer are embedded; the separate conceptual reasoner is on demand.
- LTX: Distilled BF16 Diffusers source `4791a1100e0cf97f7ed5c55c12dd71dce13f9dd3`, 8+3 deterministic Euler steps, 960×544 base followed by latent x2 upscale and refinement at 1920×1088. Video compute is BF16; audio VAE and vocoder use F32. No CFG, STG, quantization, DFR, or diffusion decoder.

LTX's native file at `49b093a39c19169a8a81721dcc541e07e945232f` stores 290 modulation tables in F32. Comfy's `av_model.py:get_ada_values` casts them to the timestep dtype, BF16 in this profile. **All 290 native tables rounded to BF16 exactly equal the selected Diffusers table values.** Serving those original tables as F32 in the unmodified Diffusers model instead promotes activations and fails at a BF16 linear layer. The supported cohort keeps the author's published BF16 Diffusers tables. This is not a new mixed-precision implementation.

The CPU ingestion client selects exact indexed Distilled shards, removes unused training-path provenance from executable config while retaining it as an asset, normalizes ten Gemma vision keys, bounds the unbounded tokenizer sentinel to 1024, and exactly widens audio weights to F32. TensorFS dtype tokens are uppercase (`F32`); lowercase tokens were caught and rejected during real qualification. The model license is an explicit asset. Serving never downloads HF files.

## CPU and UI checks

- Actual selected LTX source headers: all 6601 tensor names/shapes checked against construction. The final audio representation adds F32 storage, without changing its BF16 source values.
- Tiny full upstream pipeline comparisons: PAN2 T2V/I2V with CFG 1/2.5 give exact RGB8; LTX T2V/I2V give exact RGB8 and PCM. These are CPU implementation checks, not full-model GPU pixel parity across engines.
- LTX spatial decode matches upstream for F32 and BF16, including partial edge tiles. Retained tile outputs remain Runtime-owned between decoder calls.
- Embedded tokenizer construction matches upstream assets. For the actual PAN2 benchmark captions, Comfy and Diffusers token IDs, caption cropping, and assistant suffix match exactly: 617 positive and 1480 negative conditioning tokens.
- A fresh authenticated browser session shows both source tools on the live canvas during active GPU execution. Served controls include 1–20 seconds and first-frame input; LTX exposes resolution/audio, PAN2 exposes prompt rewriting/steps/guidance/negative caption. Both demo boxes are configured to 20 seconds. No page exceptions were observed.
- Full repository strict mypy passes with zero baseline errors; changed Python passes Ruff.

## ComfyUI comparison protocol

Use the same H200, Python/PyTorch cohort, requested dimensions, 481 frames, prompts, and sampling settings. Run one engine at a time, release idle CUDA executors, and finish large input transfers before Comfy. Distinguish model loading/server startup, cold graph execution, and warm sampling recomputations. Record output frame/audio facts and inspect real videos.

Comfy revision: Kijai contributor branch `eb9c05f9644ebf7ab14df36c824637cb1546384c`. LTX uses its core integration. PAN2 support is the explicitly **unmerged contributor PR #17755**, not a released official Comfy feature. Custom nodes are disabled. Use BF16 UNet/text, PyTorch attention, no previews or xformers; PAN2 additionally selects F32 VAE.

LTX uses deterministic Euler in both engines, changing the native Comfy template's ancestral first stage. Both use the same 8+3 sigmas, x2 latent upscaler, convolutional decoder, 512-pixel spatial tiles and 64-pixel overlap. Temporal splitting is disabled. Different tilers and attention implementations preclude a pixel-parity claim. Same integer seeds do not produce identical initial noise tensors across the engines.

For PAN2, the contributor computes timestep/modulation/residual operations in BF16 where Diffusers preserves F32. There is no CLI-only precision match. Preserve that caveat in every timing claim. The exact Diffusers sigma list, structured positive/negative captions, T2V zero conditioning, and text-layer/crop boundaries are matched; embedding and velocity numerical parity are not established.

Reject memoized Cozy results and Comfy cached sampler nodes. In particular run 30 reused run 27 and is not a timing sample. Match fresh seeds 2026111521, 2026111523, and 2026111524 for the three actual LTX recomputations. Comfy may cache model/text/empty-latent nodes between them; report the cached nodes rather than presenting that as complete recomputation.

### Published PAN2 performance context

The [IFM-maintained vLLM RTX PRO 6000 recipe](https://github.com/vllm-project/vllm-omni/blob/main/recipes/IFM/PAN2-RTX-PRO-6000.md) reports 53 minutes for 481 frames on one RTX PRO 6000 Blackwell, or 29 minutes on two, at 50 steps. The [vLLM integration benchmark](https://github.com/vllm-project/vllm-omni/pull/8602) reports 403.4 seconds on one B300 for 313 frames, or 126.8 seconds with four B300 GPUs and CFG/sequence parallelism; its cached mode reports 98.4 seconds and changes the numerical path. These are published measurements on different hardware and workloads, not direct comparisons to Cozy's H200 run. The original arXiv link is the conceptual Critique of World Model paper, not a PAN2 latency benchmark.

A sub-30-minute H200 result for the full 481-frame, 50-step workload is an engineering target, not an achieved measurement. Consumer-card targets require actual matched runs and a memory plan; speed must not be manufactured by reducing duration, steps or precision on only one engine.

## Preserved failures

- Whole-repository LTX ingestion refused ambiguous dev/distilled and duplicate shard groups. The client now selects exact indexes.
- Gemma's strict float config constructor refused canonical JSON's integral `30` for `final_logit_softcapping`; the factory restores that declared field to `30.0` without weakening config validation.
- Runtime rejected changing the placed vocoder's derived floating buffers. Prepare its reference F32 representation during CPU ingestion instead.
- LTX native-F32 candidates failed before output: runs 21–23 rejected lowercase dtype metadata; runs 24–26 rejected F32 activations at BF16 linear layers. Neither cohort is the release candidate, and their failed receipts are retained.
- A Comfy GPU startup while Cozy still occupied VRAM failed primary-context allocation. Isolate the engines; do not lower resolution or precision to force a pass.

## Consumer GPUs and Ulysses follow-up

The follow-up uses the same 481-frame, 24 fps, 1920×1088, stereo-audio LTX workload and 8+3 deterministic Euler schedule. Transformer/video weights remain BF16 and audio compute F32. These runs used the recorded 0.26.0 RC worker / Runtime 0.47.0.dev2287 cohort; the initial H200 measurements above used the released cohort. Exact software and hardware receipts are retained per run.

| --- | --- | --- | --- |
| RTX 5090 | 334.989 / 331.801, 331.551 s | 329.788 / 320.308, 319.475 s | Cozy is 3.68% slower by the two warm means |
| H100 PCIe | 262.562 / 250.808, 271.692 s | 376.609 / 353.654, 355.333 s | Cozy uses 26.30% less time by the two warm means |
| RTX 4090 | 572.523 / 564.221, 563.898 s | No completed video | No speed win claimed: Comfy exited during video decoding |

Comfy uses disk-backed loading on the consumer cards after its default loading exhausted host memory on the 5090. The 4090 comparison still disabled temporal VAE tiling to retain the original profile; a practical baseline with the upstream 128-frame temporal tiling remains unqualified. No resolution, frame-count, step-count or one-sided precision reduction was used to turn a failure into a pass.

The first Cozy 4090 attempt finished sampling but failed during a full-video F32 RGB conversion requiring a 12 GB temporary. The package now converts 16 frames at a time with the same pointwise arithmetic. All three full 4090 videos then completed; the existing CPU reference suite also passes without replacing its references. Prompt encoding is memoizable, but the measured 5090 retry did not establish a speed improvement.

Both packages now declare Ulysses degrees 2, 4 and 8. PAN2 uses its upstream context plan. LTX explicitly splits video/audio streams and their rotary positions, gathers both outputs, computes local query rows against replicated prompt keys/values, and exchanges unequal video/audio sequences for cross-modality attention. The Runtime still selects attention kernels and owns the process group. The auxiliary PAN2 caption reasoner is group-compatible and replicated.

Real CPU collectives at 2, 4 and 8 ranks match single-rank transformer outputs to floating-point roundoff. The [reproducer](check_parallel.py) documents Gloo's unequal-output-gather limitation; production frame counts are checked on actual NCCL GPUs. Four- and eight-GPU production runs have not been measured.
